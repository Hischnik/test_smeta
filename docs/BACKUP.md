# Резервное копирование и восстановление

База данных «Метраж» — один файл SQLite (`data/metrazh.db` по умолчанию) в режиме WAL. Для согласованной копии недостаточно скопировать только `.db` во время работы сервера: рядом могут находиться `-wal` и `-shm`. Поэтому используется `VACUUM INTO` — SQLite создаёт целостный снимок базы.

## Что копировать

| Данные | Путь | Обязательность |
|---|---|---|
| База данных | `data/metrazh.db` | Обязательно |
| Резервные копии БД | `data/backups/` | По желанию, храните отдельно |
| Настройки окружения | `.env` | Обязательно (секреты, адрес) |
| Исходный код | каталог проекта, без `node_modules` | Обязательно |
| Шрифты | `assets/fonts`, `public/fonts` | Входят в исходники |

## Автоматическая копия

```bash
npm run backup
```

Скрипт создаёт `data/backups/metrazh-<UTC-дата>.db`, проверяет размер и оставляет последние 30 копий. Сервер останавливать не нужно: `VACUUM INTO` даёт согласованный снимок.

В интерфейсе администратора: **Настройки → Данные → Скачать резервную копию**. Файл можно скачать в браузере.

### Расписание

Linux, cron:

```cron
30 2 * * * cd /opt/metrazh && /usr/bin/node scripts/backup.mjs >> /var/log/metrazh-backup.log 2>&1
```

Windows, Планировщик заданий:

- Действие: `node.exe`
- Аргументы: `scripts\backup.mjs`
- Рабочая папка: `C:\Game\Smeta`
- Триггер: ежедневно, например в 02:30.

Рекомендуется дополнительно выгружать каталог `data/backups/` в отдельное хранилище (S3-совместимое, другой диск, NAS).

## Восстановление

**Обязательно остановите сервер** (Ctrl+C, `systemctl stop metrazh` или остановка задачи). Иначе SQLite может повредить данные.

1. Сохраните текущую базу на случай ошибки:

   ```bash
   cp data/metrazh.db data/metrazh.db.before-restore
   ```

2. Удалите WAL-файлы, если они остались:

   ```bash
   rm -f data/metrazh.db-wal data/metrazh.db-shm
   ```

3. Скопируйте резервную копию на место базы:

   ```bash
   cp data/backups/metrazh-2026-11-08T09-00-00.db data/metrazh.db
   ```

4. Запустите сервер:

   ```bash
   npm start
   ```

5. Проверьте: вход администратора, список объектов, сумму сметы, открытие публичной ссылки, выгрузку PDF.

Есть и скрипт, который делает шаги 1–3 автоматически (сервер всё равно нужно остановить):

```bash
npm run restore -- data/backups/metrazh-2026-11-08T09-00-00.db
```

Скрипт проверяет, что файл похож на SQLite, сохраняет текущую базу рядом с суффиксом `.before-restore-<дата>` и удаляет `-wal`/`-shm`.

## Проверка восстановления

Раз в квартал:

1. Создайте копию.
2. Разверните её на тестовой копии каталога (`DATA_DIR=data-test`).
3. Убедитесь, что открываются объекты, суммы совпадают, публичная ссылка работает.
4. Удалите тестовый каталог.

## Срок хранения

- Оперативные копии: 30 дней.
- Ежемесячные копии: 12 месяцев (по требованиям заказчика срок может быть изменён).
- Копии перед обновлением/восстановлением: до подтверждения успешной работы.

## Что не входит в базу

- Исходники и шрифты — восстанавливаются из репозитория.
- `.env` — храните отдельно в защищённом месте.
- PDF-файлы не хранятся: формируются по запросу из актуальных данных.
